## 3. Top-15 BOSSNYUMBA-AHEAD-vs-LITFIN list

Surfaced from the reverse-port audit (2026-05-18) — features BOSSNYUMBA ships that LITFIN does NOT, ranked by leverage:

1. **24-dim persona-vector drift probe + alert pipeline** (`kernel/persona-drift/vectors.ts:28-53` + `alert.ts:32-33`) — LITFIN's drift detector is a single Jaccard-token-overlap scalar; BOSSNYUMBA's is a 24-dimensional vector covering tone, register, citation discipline, refusal posture, etc.
2. **Streaming kernel path with debate-inline + per-token cache replay** (`kernel.ts:575-913` `thinkStream`) — LITFIN keeps streaming outside the kernel in sibling `stream.ts`.
3. **18-tool BrainToolSpec registry with typed `platform.*` action bus** (`kernel/tool-spec.ts:510` + 18 `platform.*` tools) — LITFIN's brain-side `BrainToolSpec` has 4 calculator-style tools.
4. **Persistent privacy-budget composer** (`packages/database/.../privacy-budget-composer.service.ts:438` + migration `0116_platform_privacy_budget.sql`) — LITFIN's `computePrivacyBudget` is pure / non-persistent; BOSSNYUMBA serialises ε,δ reserves with atomic check-before-read.
5. **Tier-scaled k-anonymity lattice (k = 5 → 25 by tier)** (`kernel/cohort-signal.ts:75`) — LITFIN uses a single global k=5.
6. **AsyncLocalStorage-bound tenant-isolation enforcer with generic `TenantScoped` constraint** (`packages/ai-copilot/.../tenant-isolation.ts:41-272`) — LITFIN has a `buildTenantFilter` helper but no type-level scope binding.
7. **Two-track inviolable gates: 7-category authed + 6-category public** (`kernel/inviolable.ts:33-42` + `kernel/public-inviolable.ts:44-141`) — LITFIN has a single authed gate; BOSSNYUMBA's `public-inviolable` is the unauth-marketing-surface separator LITFIN never needed.
8. **Hash-chain HMAC-SHA-256 audit with key rotation + `timingSafeEqual` + migration 0127** (`packages/ai-copilot/.../audit-hash-chain.ts:651`) — LITFIN ships a chain verifier without HMAC rotation.
9. **Continuous grading framework — 696 LOC, 5-C `condition/cashflow/covenant/context/compliance` axes** (`kernel/continuous-grading.ts:158-535`) — LITFIN's `five-c-continuous.ts` is 404 LOC and on the credit-side.
10. **DB-backed Drizzle services for sovereign-action ledger with `pg_advisory_lock` chain protection** (`packages/database/.../sovereign-action-ledger.service.ts:182+,399`) — LITFIN's ledger has no advisory-lock concurrency control.
11. **OpenTelemetry full stack — Wave-L coordinated to 0.218** (`packages/observability/` + sdk-node 0.218) + 13 canonical kernel-step span names + bounded `AgentName` enum — LITFIN has zero OTel deps.
12. **Per-agent Grafana dashboards + judge-confidence histograms + drift alerts + OTel→Langfuse** (Phase D6 ✅) — LITFIN has no per-agent metrics surface.
13. **Temporal Entity Graph + Louvain community detection** (`packages/database/.../temporal-entity-graph.{service,louvain}.ts`, 922 LOC) — LITFIN's KG has bi-temporal indexes but no community algorithm in-tree.
14. **DB-backed sensor-routing control plane with per-tenant override** (Phase D7, migration `0149_sensor_routing_control.sql`) — LITFIN has the table; BOSSNYUMBA's D7 fills the missing piece flagged in `04-sensors-routing.md`.
15. **Tenant credit rating model** (`packages/ai-copilot/src/credit-rating/`) — BOSSNYUMBA's property-mgmt-specific equivalent of LITFIN's 5-C model, with rent-arrears + lease-tenure + occupancy axes. LITFIN's analog targets borrower credit.

## 7. Methodology

This status doc was produced by Phase-D fix-wave agent F2 (2026-05-18) by:

1. Reading every gap in `01..10-*.md`.
2. Cross-checking each "MISSING" claim against on-disk evidence via `find`, `grep -rn`, and direct `Read` of the cited file:line.
3. Categorising into SHIPPED / PARTIAL / OPEN / IN-FLIGHT.
4. Overlaying a `> ✅ SHIPPED` / `> ⚠️ PARTIAL` / `> 🔴 OPEN` callout onto the original gap row — **without deleting** the original gap text — so the doc remains readable as "here's what LITFIN had, here's what BOSSNYUMBA shipped to match or exceed it."

No source code was touched. Only `.md` files in `.planning/parity-litfin/` (+ this status doc) and the top of `.planning/litfin-parity-plan.md` were modified.
